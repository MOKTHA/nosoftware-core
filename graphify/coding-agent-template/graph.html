Repo role

coding-agent-template is Vercel Labs' reference substrate for spawning coding agents inside sandboxes and committing their output back to GitHub. It is the archetype for heynxt-core's agent substrate: adopt the contract patterns, dispatcher design, streaming persistence, and sandbox orchestration; re-implement Vercel-specific infrastructure (@vercel/sandbox, ai-gateway.vercel.sh, Vercel OAuth, Neon via Vercel integration) against the runtime heynxt-core actually targets.

Read first

  1. lib/sandbox/agents/index.ts — the dispatcher and the uniform contract boundary.
  2. lib/sandbox/agents/claude.ts — reference adapter: CLI install, gateway auth, MCP wiring, stream-JSON parsing via Writable, sessionId extraction, resumption.
  3. lib/sandbox/types.ts — SandboxConfig, SandboxResult, AgentExecutionResult. The contract to preserve.
  4. app/api/tasks/route.ts — end-to-end orchestration: Next.js after() for long-running work; three parallel after() blocks (branch name / title / task execution); the timeout Promise.race; the "capture session before entering after() because session is not accessible inside" pattern.
  5. lib/sandbox/creation.ts — sandbox lifecycle (clone, install, dev server, git branch, browser skill install).
  6. lib/db/schema.ts — 7 tables + encryption story.

Six adapters · one contract

Each file in lib/sandbox/agents/{claude,codex,copilot,cursor,gemini,opencode}.ts exports one function (sandbox, instruction, logger, …) => Promise<AgentExecutionResult>. They differ only in: CLI install, config-file format, auth, streaming parser, resume flag. Adding a 7th agent = write a new file + one switch case in index.ts. Copy this pattern verbatim.

Sandbox + streaming pattern to adopt

  • Run CLI in an isolated container via an SDK exposing runCommand({cmd, args, env, cwd, stdout: Writable, stderr: Writable, detached, sudo}).
  • Feed a Writable whose write(chunk) splits on \n, parses each line, and incrementally updates a DB row via drizzle.update(...).set({content: accumulated}).where(eq(taskMessages.id, agentMessageId)). Fire-and-forget .then().catch() — UI polls the row.
  • For non-JSON agents, line-prefix-filter and wrap in <pre>.
  • Completion signal = explicit chunk (e.g. type === 'result') or process exit. Poll loop is safer than awaiting detached process directly.
  • Always redact secrets via redactSensitiveInfo(); never log dynamic user values (see AGENTS.md).

Session resumption

Store sessionId on the task row after each run. Follow-up messages pass (isResumed: true, sessionId); adapter translates to per-agent resume flag. Keep sandbox alive if keepAlive: true; otherwise destroy after completion.

What NOT to re-implement

  • Vercel Sandbox provisioning internals — reimplement against your container runtime but keep the create/configure/execute/teardown lifecycle shape.
  • AI Gateway URL — substitute your gateway or direct provider SDKs; keep the proxy-everything pattern.
  • Vercel+GitHub OAuth via arctic as configured — use your auth; keep the identity-merging pattern.
  • AES-256-CBC via Node crypto — use a KMS or framework secrets; keep per-user encrypted keys.
  • Neon-specific Postgres client — use any Drizzle-compatible driver; keep the schema shape.
  • JWE session implementation — use your framework's sessions; keep encrypted server-readable sessions carrying user id + provider tokens.
  • Agent CLI install scripts (curl URLs, npm package names) — treat as content, not architecture.

What to re-implement from scratch

  • Container runtime + lifecycle hooks.
  • Model gateway / key management surface.
  • Authentication and identity merging against heynxt-core providers.
  • Task queue / background execution mechanism (a proper queue is likely better than after()).

Files that matter most

Keep the 4-file core stable across adaptations: dispatcher (agents/index.ts), reference adapter (claude.ts), contract types (types.ts), orchestrator (task route). Anything built atop these four is replaceable.
